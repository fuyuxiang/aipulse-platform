# AIPulse 前端产品化整改与验收

日期：2026-11-04。范围：本地工作区前端产品形态、核心操作闭环，以及为这些操作补齐的服务端校验；保留此前的后端与 Runtime 整改，未部署生产环境。

## 产品结构

采用浅色控制台、固定导航、紧凑页头、单一主要操作与一致的状态表达。品牌统一为 AIPulse；参考图片仅用于视觉层级分析，没有复制其品牌、业务内容或菜单实体。

| 页面 | 整改前 | 本轮实现 |
| --- | --- | --- |
| 全局框架 | AgentOS 品牌、静态 RBAC 标签、通用后台导航 | AIPulse、权限导航、面包屑、页面搜索、快捷新建、手机抽屉与账号菜单 |
| 首页 | 大型宣传标题、重复指标、较长页面 | 可用工作入口、真实资源数量、最近创建、配置引导、服务检测；数据失败不伪装成零或健康 |
| 资源列表 | 列表前堆叠统计卡和 JSON 操作台，约 866 px 后出现表格 | 标题、搜索/筛选、列表优先；高级操作折叠；增加详情、编辑、启停、删除和持久化反馈 |
| 智能体 | 通用新建与向导并列，模型类型混入向量/重排 | 统一创建/编辑向导、生成式模型筛选、资源选择、记忆和审批开关、跨步骤保存与离开保护 |
| 工作流 | 统计、筛选、画布、操作台及列表纵向混排 | 独立编辑器、节点库、连接端口、节点/边配置、保存/校验/试运行、URL 恢复、加载竞态处理和离开保护 |
| 对话 | 通用空态、部分错误静默、历史选择和输出组织较弱 | 任务引导、历史恢复与分页、消息刷新、失败反馈、重新生成、Markdown/表格/代码、复制、反馈、输入法保护 |
| 团队 | 运行触发无关拓扑展示，输出以原始 JSON 为主 | 独立详情/执行/历史、成员名称与职责、编辑与原子保存、执行状态和实际输出 |
| 发布 | API 凭证误连系统配置，版本使用通用资源页 | 独立 API 发布/凭证详情/停用/轮换与版本快照/发布/回滚页面；API 发布可选择版本 |

后台配套修复：版本及运行列表按智能体过滤；跨智能体版本发布拒绝；回滚目标验证；团队编辑先验证全部引用再统一提交；资源编辑回传 `***` 时保留服务端原密钥，响应和审计仍脱敏。

## 可用性边界

- 本轮完成的关键界面与闭环以实际测试为准；26 个导航入口冒烟证明页面与读取请求可正常打开，不代表每个专业模块的全部业务分支都经过人工验收。
- 真实模型验证覆盖普通用户对话及历史、发布 API、真实向量与重排、知识源匹配、实际计算工具调用及三成员流水线；不承诺每个模型都支持工具调用。
- 现有运行时仍存在已识别的边界：Chat/Team 中 Agent 内部工具审批没有通用自动续跑；团队没有正式任务/成果验收状态机；复杂工作流汇合/循环/恢复与发布依赖快照仍需后续建设。界面不将等待审批或失败标成完成。
- 评测当前对导入的实际回答评分，并非自动调用 Agent 的评测流水线。
- 首包已拆分，图编辑器与专业页面按需加载；Webpack 仍有体积建议警告，尚未进行正式生产网络与容量压测。
- 依赖审计仅代表检查时的已知公告结果，不等同于生产安全认证。
